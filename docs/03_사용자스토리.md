# 회의실 예약 서비스 사용자 스토리

### S1. 겹치는 예약 막기
- 스토리: 회의실을 예약하는 직원으로서, 겹치는 예약을 막고 싶다. 예약 시간 충돌을 방지하기 위해서다.
- 인수 조건:
  - 겹치는 예약은 허용되지 않는다.
  - 겹침의 세부 기준(예: 예약 종료 시각과 다음 예약 시작 시각이 같은 경우)은 **확인 필요**.

### S2. 정원을 넘는 예약 막기
- 스토리: 회의실을 예약하는 직원으로서, 정원을 넘는 예약을 막고 싶다. 회의실 수용 인원을 지키기 위해서다.
- 인수 조건:
  - 정원을 넘는 예약은 허용되지 않는다.
  - 정원과 참석 인원이 같은 경우의 처리 등 세부 기준은 **확인 필요**.

### S3. 예약 현황판 만들기
- 스토리: 회의실 이용 현황을 확인하려는 직원으로서, 예약 현황판 웹페이지를 이용하고 싶다. 예약 상황을 파악하기 위해서다.
- 인수 조건:
  - 예약 현황판 웹페이지를 제공한다.
  - 페이지에 표시할 정보와 공개 범위는 **확인 필요**.

### S4. 예약 취소 기능 만들기
- 스토리: 예약을 관리하는 사용자로서, 예약을 취소할 수 있기를 원한다. 더 이상 필요하지 않은 예약을 정리하기 위해서다.
- 인수 조건:
  - 예약 취소 기능을 제공한다.
  - 취소할 수 있는 사람과 취소 후 현황에 반영되는 방식은 **확인 필요**.

### 확인 필요
- **최대 예약 시간(2시간 또는 4시간):** 강도윤 팀장이 정책 확정 예정.
- **노쇼 자동 취소 기준(10분 또는 15분) 및 이번 범위 포함 여부:** 회의록에 결정 담당자가 지정되어 있지 않음.
- **현황판 연락처 표시 여부 및 외부 공개 여부:** 회의록에 결정 담당자가 지정되어 있지 않음. 강도윤 팀장이 외부 공개 여부 확인 필요성을 제기함.
